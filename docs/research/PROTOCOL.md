# Preregistered phased protocol

## How to use this document

This is an executable **research plan**, not a claim that a native runner exists. Run only a phase whose predecessors have passed in a saved decision record. Today the repository delivers the finite reference artifact described by the [README](../README.md); native phases require new implementation and are explicitly unexecuted. A future successor must implement the specified interfaces before attempting the associated command, not invent a result for an absent tool. [THESIS.md](THESIS.md) defines the finite semantics and claim ladder; [BASELINES.md](BASELINES.md) defines matched comparisons; [THREATS.md](THREATS.md) defines refusal and checker validity.

Freeze protocol revision, code/environment hashes, input manifest, seed list, bounds, budgets, and checker contracts before each phase's first outcome inspection. Changes after inspection create a new protocol revision with a reason and separately reported runs. Never move a threshold to rescue an observed failure. A transient failure gets at most one exact rerun and one declared cause-directed adjustment; a repeated failure stops that branch. Infrastructure failure is “blocked/incomplete,” not scientific falsification or success.

Initial exploration is **two actors, at most two preemptions**, with the preemption definition in THESIS. Finite differential research starts with at most **eight total modeled events** and values `{0,1}`; increasing a bound requires a new declared experiment. Native actors must account for every independently scheduled thread; uncontrolled background threads are not silently absorbed into a two-actor claim. All numeric cutoffs below are sole-author engineering investment gates, not significance tests or statistical laws.

## Common evidence bundle

Each completed, failed, timed-out, unsupported, or diverged run gets an immutable run directory keyed by a unique run ID; never mix reruns. Save:

- protocol/code/model/backend/checker versions; OS/kernel, toolchain, filesystem/mount/cache modes; command argv/environment allowlist; process topology and scheduling granularity;
- subject upstream URL, immutable revision/archive hash, license text hash, dependency/binary hashes, input and clean-image hashes, permitted root and resource limits;
- full schedule decisions and enabledness/preemption accounting; seed; event trace with errors/short I/O, provenance, barriers, admitted-image explanation, and crash-request acknowledgment;
- pre-recovery image hash/copy, survived/lost effects, recovery argv and exit/output, checker verdict and observations, acknowledged promises, unsupported/divergence reasons;
- search/reset/recovery/checker/minimization CPU and wall time, peak memory, schedules/frontiers/prefix samples/unique images, outcome set, and root-cause deduplication rationale;
- replay attempts, denominator, successes and divergences; final gate decision and blocked descendants.

Native output schema must distinguish `pass`, `semantic_violation`, `unsupported`, `replay_divergence`, `timeout`, and `infrastructure_error`; exit-zero alone is not the schema. A timeout or unsupported trace never becomes a pass. Publish safe raw evidence and negative rows, subject to disclosure restrictions in THREATS.

## Gate 0 — finite sanity, not native feasibility

**Input:** canonical finite executable, documented run command, declared existing-record semantics, explicit unsafe/safe programs and recovery predicates. Use the README's actual invocation and save its emitted result rather than stale scratch-probe counts. No downloads, native injection, or third-party workload execution is needed.

From the repository root, run the delivered entrypoint:

```sh
python3 -m durability_debt probe --output /tmp/durability-debt-probe
```

The output directory must not already exist; choose a fresh name for a rerun rather than overwrite evidence. The canonical launch bundle is `results/launch/report.json` with `results/launch/manifest.json`. Delivered cases are `publish_before_flush`, `flush_before_publish`, `old_version_consumer`, `no_relevant_sink`, `independent_logger`, `self_validating_cache`, `single_process_missing_flush`, and `independent_noise`. Baselines are `seed_cartesian` (producer-first), `bad_seed_cartesian` (consumer-first), `joint_cartesian`, `reversed_joint_cartesian`, and `joint_extrema`. Extrema is an elementary exact-**existence** comparator only for independent integer-order predicates, not full outcome preservation or a new reduction. The canonical probe records both seed results, equality of complete joint outcome sets under reversed search order, all negative controls, and no-crash controls.

**Procedure:**

1. Run bounded Cartesian enumeration and every delivered baseline over identical cases. Distinguish schedules, crash frontiers, prefix-choice samples, unique disk images, and distinct checker inputs/outcomes.
2. Inspect one violating witness: show actual actor order, consumer read value, selected source/sink persistence prefixes, flush lower bounds, and failed predicate. Confirm it is admitted without adding semantic source-to-sink requirements to storage `pb`.
3. Nominate S-good and S-bad as in BASELINES **before** comparison. Exhaustively explore crash choices for each seed separately; reverse the seed used by alternate-schedule search. Preserve both results, including any baseline success on S-bad.
4. Check unsafe handoff, safe flush-before-handoff, old-version consumer, no relevant sink, independent durable logger, validating/rebuilding cache, and no-crash controls. Only list controls actually implemented/exercised as passed; missing cases block the corresponding gate row rather than inheriting a pass from unsafe/safe examples.
5. Ensure deterministic rerun gives the same canonical outcome sets. The finite checker compares declared records, not a SQLite database or Linux recovery procedure.

**Pass:** unsafe admits the intended source-old/sink-new failure under S-bad; S-good lacks that corresponding failure; safe and semantic negative controls have zero rejected outcomes. Compare outcome sets only for explorers claiming full preservation, and compare violation existence only for the restricted `joint_extrema` contract. Ordinary one-trace failures must be classified separately. **Stop/fix:** illegal images, unexplained disagreement, nondeterminism, or false-positive controls. Gate 0 pass earns C1 only; it does not earn the methods thesis or authorize calling the artifact a native tester.

**Cap:** 10 minutes CPU, 1 GiB memory, 100 MiB output per reference invocation. A bound-explosion timeout is reported incomplete; do not silently reduce the workload and call the original gate passed.

## Gate 1 — prior art and strongest-composition stop

**Input:** Gate 0, pinned predecessor sources/artifacts, an explicit candidate algorithm/property or an honest absence thereof. The hostile review is binding on framing: PerSeVerE already owns joint semantics/DPOR/recovery observation; PMRace/DURINN own visible-before-durable; RACEPRO × ALICE/Pathfinder × LazyFS is the obvious composition (primary links in THESIS and BASELINES).

**Procedure:**

1. Write a claim-to-predecessor matrix and run translated finite litmuses through actual PerSeVerE where legally and technically available. Record translation and model differences. An unrun artifact is not an independent oracle.
2. Implement/measure B4 and PerSeVerE-like explicit-observer pruning before claiming a new reduction. Fix the same model/checkers, allow normal canonical caching and standard optimizations, and compare outcome languages, not just counts.
3. Define a candidate product-aware independence/equivalence relation and an effective exploration algorithm. Prove its stated preservation property, or explicitly use heuristic status. Separate execution/read-from, storage legality, and semantic requirements. Never put a desired application obligation in `pb` to eliminate the bad state.
4. Generate every well-formed program in a **published finite grammar** up to eight events/two actors/two preemptions/values `{0,1}`, canonicalizing symmetries. Freeze the grammar and list exclusions before enumeration. The initial grammar contains only implemented whole-record operations, not wished-for namespace or interval features. Compare full unique checker-observable outcome sets against B0. An incomplete enumeration cannot be presented as exhaustive.
5. Include a non-monotone predicate, overwrite/version changes, barrier/read reorderings, blocking handoff, logger/cache controls, and mutants deleting each claimed necessary dependency rule. Every mutant claimed unsound needs a minimal missed/illegal-outcome counterexample. Namespace, mixed-read, negative lookup, and shared-offset counterexamples are mandatory **before a later extension claims those operations**, not fake coverage of the initial record model.
6. Exhibit and justify a parameterized family where the proposed mechanism merges product cases that the strongest independent composition cannot. Distinguish asymptotic representative-count separation from constant-factor implementation savings, ignoring unobserved records, and simple extrema pruning.

**Advance only if:** exact outcome equality on the complete generated bound, no illegal images, every necessary-rule mutant has a counterexample, a clearly stated preservation argument survives hostile review, and a mechanism-specific separation from B4 exists that is not already PerSeVerE observer pruning. A finite table is supporting evidence, not proof of an asymptotic claim. If using a heuristic instead, explicitly abandon the exact-reduction claim and obtain a new project decision before native scale-up; do not silently reinterpret this gate.

**Kill the proposed methods thesis if:** it is only generic POR followed by persistence-ideal enumeration; only a min/max shortcut for the motivating predicate; a renamed known pattern; any unresolved bounded counterexample; or no defensible difference from adapting PerSeVerE. Preserve a reference-model/prior-art negative artifact. Do not build a large native system to postpone this decision.

**Investment cap:** 40 author-hours on the candidate reduction after Gate 0, at most 4 CPU-hours total finite enumeration, 4 GiB memory and 2 GiB generated output. If the complete stated grammar cannot finish, report that bound incomplete and reconsider the claim explicitly; never substitute a sample as “all.”

## Gate 2 — separate safe native feasibility and SQLite litmus

**Input:** Gate 1 advancement, explicit native event/storage contract, legitimately available rootless execution dependencies, disposable storage root, working unsupported-event refusal and timeout containment. Missing `fuse3` development headers/libraries is a prerequisite blocker, **not permission to sudo, install system packages, alter FUSE policy/ptrace/SELinux, or change host security**. Record the unavailable requirement and stop native work. A finite replayer is not a native fallback pass.

Start with restricted buffered regular-file data and supported process/pipe events. A supervisor must observe/control process events independently of FUSE requests. Fix mount/cache mode and establish supervisor-request correspondence. [Linux FUSE I/O documentation](https://docs.kernel.org/filesystems/fuse/fuse-io.html) describes caching and request splitting; daemon request order is not application syscall order. [LazyFS](https://www.vldb.org/pvldb/vol17/p3017-ramos.pdf) is a candidate data fault executor, not metadata crash coverage or arbitrary subset realization. Inventory exact controllable faults and require acknowledgment before recovery.

**Source-to-SQLite experiment (planted composition litmus, not an upstream SQLite bug):**

1. In the disposable mount, create and durably initialize fixed-size `source.json` with version 1 and `state.db` with schema `(version, digest)`. Flush initialization and required directories. Store immutable baseline hashes. No real repository/database is an input.
2. A overwrites source with version 2, delaying its flush; a pipe handoff makes B eligible. B reads source, computes SHA-256, and uses the unmodified SQLite library/CLI to commit version/digest. Start with rollback-journal mode, `synchronous=FULL`, and `mmap_size=0`; record actual effective settings and SQLite build/VFS.
3. Supervise S-good and S-bad: in S-good A's flush completes before B's relevant read; in S-bad B reads/commits before A's flush. Record concrete read bytes, barrier returns, and commit success. A plain sleep or favorable timing is not a replay scheduler.
4. Freeze the tree at the declared frontier; inject only a backend-supported, model-admitted source-lost/sink-survives image. Do not hand-delete SQLite journal/WAL files or assume cache clear models namespace loss. If the intended image cannot be safely realized or its journal/metadata state justified, fail this gate rather than constructing a favorable but illegal database.
5. Terminate only supervised processes, restart from actual selected backing state with cache-isolation evidence, open SQLite so its real recovery runs, execute `PRAGMA integrity_check`, and compare recovered source SHA-256/version to a committed row whose contract requires current-source correspondence. Structural integrity and cross-resource semantics are separate checks ([SQLite commit](https://sqlite.org/atomiccommit.html)).
6. Repeat saved S-bad witness from clean initialization ten times. Run ten each of S-good, no crash, flush-before-handoff (including required namespace flushes), old-version/no-publication consumer, unrelated logger, and digest-validating cache recovery. Controls must state their own allowed observations; logger/cache may have taint but must not be called bugs.
7. Attempt WAL only as an explicit coverage extension. `mmap_size=0` does **not** by itself establish absence of WAL shared-memory coordination ([WAL documentation](https://sqlite.org/wal.html)). Trace/support or reliably refuse the actual WAL/shm/locking behavior. A refused WAL run is expected unsupported coverage, not a passed WAL test. Never claim rollback-mode success covers WAL.
8. Inject representative unsupported accesses and trace/replay divergence; verify refusal without reporting safety or executing faults outside the disposable root.

**Pass:** alternate schedule changes actual observation/order; nominated good trace's complete supported crash exploration lacks the corresponding failure; native image legality is justified; S-bad replays >=9/10 clean-image attempts; every supported negative control passes 10/10; unsupported events are refused 100%; no escaped writes or targets. The 90% replay gate is a minimum operational floor, not deterministic replay or general reliability. Investigate every failed replay and publish denominators.

**Kill closed-box native claim:** source edits to targets or custom kernel are required; critical events cannot be observed/refused; FUSE-only gating is the only schedule control; image legality is unverifiable; or replay/controls fail after the bounded correction loop. **Cap:** 40 author-hours feasibility, 8 CPU-hours experiment total, 4 GiB memory, 5 GiB disposable data, 60-second run/watchdog deadline. CPU-only, one mount, no privilege escalation or physical power loss.

**Procedure:** acquire all six and freeze selection/checkers before fault runs. Establish no-crash/recovery controls first; use BASELINES B0–B6 wherever supported under identical budgets. B0 may exhaust only a bounded projection, which must not be confused with full native completeness. Limit baseline families to the preregistered seven IDs; variants subdivide the same budget rather than receive hidden extra time.

**Advance only if all:** all six classes have qualifying supported workflows; at least one checker-confirmed **unmodified real composition** exhibits an incremental schedule-conditioned failure versus the nominated one-trace baseline; preserved in-bound finite witness recall remains 100%; matched completed pilot searches show >=10x median fewer checked images than B0 **and >=2x median end-to-end improvement over strongest B4** at equal confirmed-outcome coverage; replay >=90%; all safe/logger/cache controls pass; untriageable checker failures <=10%; median bespoke checker logic <=50 nonblank lines and median checker authoring <=4 hours per workflow. Reused oracle code is counted separately, not hidden. These margins compensate for implementation/maintenance costs; small wins against exponential strawmen are insufficient. If B4 already saturates tiny spaces, record absence of discriminatory power and do not assert a ratio. If the candidate is only faster by dropping failures, it fails.

**Stop:** no incremental real witness, composition parity, excessive unsupported scope/checker effort, or cheap B6 prevention without a distinct diagnostic benefit. Preserve negative pilot with all exclusions; do not broaden into networks, kernel work, or a new brand. **Resource cap:** 28 CPU-hours total seven-method pilot, 8 GiB memory, 10 GiB scratch; at most 24 author-hours checker work plus separately logged triage. Budgets include repeats; if exhausted, report incomplete.

## Gate 4 — twenty real workflows, only after Gates 0–3

Use W1–W6 allocations `4+3+4+4+3+2=20`, counting pilot members. Acquire/freeze all additions under the same criteria before outcome inspection. A workflow is a distinct documented operation/dataflow contract, not a seed, input size, journal-mode toggle, planted bug, or wrapper around the same action. Report shared upstream projects so twenty workflows are not presented as twenty independent systems. If the roster cannot supply twenty qualifying real workflows without artificial promises, stop the prevalence/generalization claim.

Keep two actors/two preemptions unless a separately justified scope extension has passed its own model/refinement gates. Same methods/seeds/caps/checkers as Gate 3; total experiment cap 94 CPU-hours, 8 GiB memory, 20 GiB scratch, 80 author-hours additional adaptation/triage. Stop on safety or soundness failure immediately; report all early stopping. Reproduce each distinct failure >=9/10 same-host clean-image attempts and, when an independently available environment/operator exists, seek independent reproduction; absence blocks independence claims, not permission to fabricate confirmation.

**Full thesis survives only if:** there is nonzero incremental real schedule-conditioned failure discovery beyond both one-trace and random schedule/crash under matched budgets; advantage is not confined to planted/ordinary missing-fsync cases; Gate 3 coverage/efficiency/replay/triage thresholds still hold on the full declared supported set; and hostile novelty review still identifies a substantive product mechanism/capability. Report effects per workflow and root cause, uncertainty and censored rows; no prevalence estimate from this convenience corpus. Zero incremental real failures across twenty is a fixed kill of the empirical flagship thesis even if an attractive microbenchmark remains.

## Decision and publication

A passing finite probe supports a public reproducibility/reference note only. A Gate 1 negative supports a precise composition-equivalence/counterexample/prior-art report; a Gate 2 blocker supports a feasibility report with exact missing prerequisites; Gate 3/4 negatives support a pinned corpus/checker and honest empirical null if licensed and useful. None requires pretending a positive paper exists.

Consider a full methods/systems journal submission only after a substantive defended reduction or explicitly redesigned empirical contribution, native refinement evidence, strong baseline results, independent review, disclosure-safe artifacts, and candid scope limitations.
